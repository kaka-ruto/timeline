## Plan: Mobile Responsiveness Improvements

After thorough exploration, here are the specific issues and their fixes across all pages.

### File 1: `src/layouts/AppShell.astro` — Layout fixes

**1a. Bottom nav safe-area padding for notched devices**
- Add `pb-[env(safe-area-inset-bottom,0px)]` to the bottom nav's class list so content isn't hidden behind iPhone home bar.

**1b. Larger bottom nav tap targets**
- Change `px-3 py-2` to `px-4 py-3` on nav link pills for better touch targets (closer to Apple's 44pt HIG).

**1c. Close menu dropdown on scroll**
- Add a scroll listener (in the inline script) that auto-closes the hamburger dropdown when the user scrolls, improving UX.

**1d. Add `initial-scale=1` to viewport meta**
- Change `<meta name="viewport" content="width=device-width">` to `content="width=device-width, initial-scale=1"` for proper mobile scaling.

---

### File 2: `src/styles/global.css` — Content readability

**2a. Add max-width to `.content`**
- Change `max-width: none` to `max-width: 75ch` so article text has comfortable line lengths on larger screens (still full-width on narrow mobile since 75ch exceeds viewport).

**2b. Responsive font sizes**
- Use `clamp()` for headings:
  - h2: `font-size: clamp(1.125rem, 5vw, 1.5rem)` 
  - h3: `font-size: clamp(1rem, 4vw, 1.25rem)`
- Body text: add `font-size: clamp(0.9375rem, 3.5vw, 1rem)` for readability.

**2c. Overflow protection**
- Add `overflow-wrap: break-word` and `word-break: break-word` to `.content p` and `.content li` to prevent long strings from breaking layout.

**2d. Table responsive wrapper**
- Wrap `.content table` in `overflow-x: auto` handling — add `scroll-margin` or `display: block; overflow-x: auto` to the table itself.

**2e. Code block sizing on mobile**
- Set `pre code { font-size: 0.8125rem; }` on mobile so code blocks don't force horizontal scroll unnecessarily.

**2f. Image width constraint**
- Ensure `.content img` has `max-width: 100%` (already inherited from Tailwind base, but add `height: auto` explicitly).
